基本方針: 取得したデータの保存先・処理先は原則として利用者の端末内です。 外部に送るのは「利用者が自分で接続したサービス」「利用者が AI を有効にした場合の AI 処理先」 「利用者が有効にした場合の SMTP 送信先」のみで、開発者のサーバーには送信しません (OAuth 連携を含め、連携機能はすべて利用者の端末上で動作します)。

1. Google API Services User Data Policy への準拠

本サービスは Google API から情報を取得するため、次の宣言を行います。

Lucid Pair's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

参照: Google API Services User Data Policy / OAuth 2.0 Policy

補足(日本語):

  • Google API から取得したデータを広告目的に使用することはありません。
  • 取得したデータを人が直接閲覧・精査する用途(開発者による目視確認など)には用いません。 処理は機械的(自動解析・マスク・要約)であり、出力内容は利用者に提示される形でのみ確認できます。
  • Google API から取得したデータを、AI モデルの学習データとして使用することはありません。
  • Google API から取得したデータを、他のアプリ・第三者(外部の AI 処理先を含む)へ渡すことはありません (第 5 節参照)。

3. Google のデータ(申請するスコープと用途)

申請するスコープはすべて読み取り専用(read-only)で、書き込み権限は要求しません。 Google が「機密(sensitive)」「制限付き(restricted)」に区分するスコープについて (Restricted Scopes(制限付きスコープの一覧) / Google API のスコープ一覧 参照)、 宣言済みのスコープは次のとおりです。

スコープ区分取得するデータ用途
openid / email / profile非機密表示名・メールアドレスどのアカウントの接続かを表示するためだけ(現在付与済み)
calendar.readonly機密予定の件名・日時・説明予定のリマインド(予定時刻の 10 分前)の生成
gmail.readonly制限付き件名・本文(最大 2,000 文字)・送信元・日時優先度判定・要約・約束の抽出(このスコープは Google の追加の検証とセキュリティ評価の完了後に申請します)
段階的な申請方針: 制限付き(restricted)スコープである gmail.readonly は、 Google による追加の検証とセキュリティ評価(CASA)を伴うため、検証が完了するまで同意画面には含めません。 まず機密スコープ(カレンダー)だけで公開し、Gmail 対応は評価の完了後に追加する予定です。 新しいスコープを追加するたびに、この表と同意画面の宣言を更新します。

Google API のレスポンスをディスクにキャッシュせず(取得のたびに API を呼びます)、 保存するのは、マスク処理を通した件名・本文・予定情報と、そこから作成した要約だけで、利用者の端末内 DB に保持します。 削除操作を行うか、データフォルダを削除するまで保持されます。同期カーソル(差分取得の位置)のみが ローカルに記録されます(内容ではありません)。

3.1 連携を切断したとき

  • 連携センターの「切断」操作で、保存済みの OAuth トークンを破棄し、 Google 側に対してトークンの失効(revoke)を要求します。
  • 切断の確認時に「このアカウントから取得した端末内の記録も削除する」を選ぶと、 その接続のイベント(マスク済みの本文)・同期状態・重複候補・生成済み提案を端末内から削除します (削除後は復元できません。空欄の領域もゼロ書きされます)。
  • 選ばない場合、すでに端末内 DB に保存済みの記録は自動で消えません。 アプリ内の削除操作、またはデータフォルダ全体の削除で消せます。
  • Google アカウント側からも、アカウント設定 →「接続済みアプリ」/「サードパーティーのアクセスと共有」 から取り消せます。その場合、次回の同期で再接続(再同意)を求められます。

4. 画面キャプチャについて

  • 平常時は画面を撮影しません。画面監視は既定で無効 (monitor_screen_enabled = false)です。
  • 画面監視を有効にした場合は、公式 API がないサービス(例: TimeTree)を含め 利用者が指定した定点領域だけを 0.7 秒〜の間隔で取得し、 内容を言語化(要約)した時点で画像を破棄します(保存しません)。
  • 「後回し」ボタンのスクリーンショットは、利用者がボタンを押した瞬間だけ取得します。 これは操作の同意とみなされ、端末内にのみ保存されます。
  • 画面解析に用いた画像は、解析後にメモリ上で破棄します(保存しません)。

Google ユーザーデータは外部 AI へ送りません。 Google API から取得したメール本文・予定は、端末内のルールベース処理(重要度判定・要約・約束の抽出)でのみ扱い、 外部の AI 処理先へは送信しません。AI 処理先へ送信するのは、利用者の画面から取得した画像と Google 以外のサービス由来テキストです。

理由は、AI 処理先の無料枠では、送信された入力と出力が当該提供元のサービス改善や人によるレビューに 利用され得るためで、Google ユーザーデータを扱わない構成にしています (AI 処理先の規約: Gemini API Additional Terms of Service)。
  • 上記以外の第三者(広告・解析など)へデータを送ることはありません。 データを販売・提供することもありません。 開発者が AI 学習等の目的でデータを送ることもありません。AI 処理先でのデータの扱いは、 利用者が使用する API キーのプラン(無料枠/有料枠)に応じた提供元の規約に従います。
  • SMTP 送信は既定で無効です。有効にする場合は、利用者が自分の端末の設定ファイル (環境変数 / .env)に SMTP サーバー・送信元・認証情報を記載します (アプリの画面から入力する項目ではありません。この認証情報は OS キーチェーンには保存しません)。
  • 外部への書き込み(メール送信・削除・コマンド実行)は、利用者の承認を通過した場合にのみ実行されます。

6. セキュリティ

  • 保存したスクリーンショットと設定ファイルのアクセス権は、現在のユーザーだけに限定しています。
  • タイトル・本文・固有名は、秘密情報検出によるマスク処理を通してから保存します。
  • 通信は TLS(HTTPS)で行い、接続先は許可リスト(loopback 優先)で制限します。
  • 監査ログはハッシュチェーンで、改ざんを検知できます。
  • 削除したレコードは、SQLite の secure_delete により空き領域もゼロ書きされます。

7. 保持期間と削除

  • タスク・後回し記録は、利用者が削除した時点で DB と保存画像の両方が削除されます。
  • 「後回し」のスクリーンショットを削除すると、PNG ファイルも同時に削除されます。
  • 外部サービスへの接続は、連携センターから切断できます(Google / Discord には revoke を要求)。
  • すべてのデータ(設定・DB・画像)は、アプリケーションのローカル保存領域 (%APPDATA%\personal-concierge)にあり、このフォルダを削除することで一括削除できます。
